# 演示界面设计规划（原理验证版）

- 版本：v1.0（待确认）
- 日期：2026-09-15
- 范围：**仅设计规划**，不含代码实现
- 目标：把"通用自动化测试软件平台"的分层实现，通过两个界面真实、可讲解地展示出来

---

## 0. 背景与目标

本项目为**原理验证原型**，除功能可用外，还需要把"六层架构 + 层间流转"在界面上呈现给内部评审：

1. 第一个界面 = 测试软件使用人员的**操作台**（流程控制、仪器操作、报表）；
2. 第二个界面 = 各层实现与**相互关系**的架构台；
3. 所有展示由**真实执行**驱动（仿真阶段同样走完整链路，只是 HAL 用仿真实现）；
4. 架构必须支持**多仪器、多协议**持续扩展，不能只针对示波器。

---

## 1. 需求决策汇总

| 项 | 决策 |
|---|---|
| 窗口 | 两个独立窗口；不严格要求谁在上层，**以激活为准** |
| 启动位置 | **不记忆**上次位置，按默认位置启动 |
| 窗口1 尺寸 | 约屏幕面积的 1/2，可拖拽放大缩小 |
| 窗口2 尺寸 | 全屏（单屏时与窗口1 叠加；双屏时置于副屏更佳） |
| 窗口生命周期 | 不联动，各自独立关闭 |
| 左区（1/3） | 上=流程控制与参数；下=流程编辑与显示 |
| 流程编辑 | **非自动测试时可编辑**；自动测试运行时只读+高亮 |
| 中区（1/3） | 仪器坞：一个仪器一个子模块；自定义面板；勾选显示；分隔条调大小 |
| 仪器布局 | 1 台占满 → 2 台上下分栏 → 3~4 台 2×2 → 更多用标签页（数量不设限） |
| 运行中仪器 | 用户可自由切换查看 |
| 右区（1/3） | 报表：**总表**累积；仅允许配置"哪个测量项填哪列"，数值不可改；需上下限 Pass/Fail；暂仅导出 HTML |
| 架构台 | 只读展示，不做内容交互；**非自动测试期间可添加资产（算法库/方法/驱动）** |
| 暂停语义 | 当前步骤执行完毕后暂停；**暂停期间不执行任何动作**，保持现状等待继续 |
| 停止语义 | 停止调度后续步骤，并**自动回安全态**（如自动断电、输出关闭） |
| 波形计算 | 一期：数学/算法模块（加减乘除、峰峰值/有效值、频率/周期/占空比、滤波、FFT 峰值）；自定义脚本留二期 |
| 数据源 | 前期用仿真；真机通路保留 |
| 统一能力模型 | **采用**（混合模型：能力声明 + 原生命令逃生口） |
| 仪器发现 | 完成一期（手工添加+连接测试）与二期（网段扫描 + VISA 枚举） |
| 并发 | 不严格并发（串行调度 + 步骤级超时） |
| 演示对象 | 内部使用；不需要一键演示、不需要录屏导出；架构台**不做流动动画** |

## 2. 总体结构

### 2.1 双窗口

```text
┌─ 窗口2 架构台（全屏，可激活到最前） ─────────────────────┐
│  ┌─ 窗口1 操作台（约半屏，可激活到最前/拖拽缩放） ──────┐ │
│  │  左 1/3 流程控制+编辑 │ 中 1/3 仪器坞 │ 右 1/3 报表 │ │
│  └──────────────────────────────────────────────────┘ │
│   层卡片 · 层间连线 · 命令日志 · 资产注册入口             │
└───────────────────────────────────────────────────────┘
```

- 两窗口**平等**，谁被点击谁到最前（不强制层级）；
- 单屏：窗口2 全屏，窗口1 默认居中偏上；双屏：窗口2 建议放副屏；
- 每次启动按默认几何；不做位置记忆；
- **提供"隐藏 / 显示窗口2"开关**（按钮 + 快捷键）：一键隐藏全屏架构台，只留操作台；
  用于虚拟机 / 远程桌面 / 单屏投屏等两窗口互相遮挡的场景。隐藏期间事件仍在后台记录，重新显示即可看到完整日志。

### 2.2 窗口1 三区结构

```text
┌─────────────────────── 窗口1 操作台 ───────────────────────┐
│ 左 1/3                     │ 中 1/3            │ 右 1/3      │
│ ┌───────────────────────┐ │ ┌───────────────┐ │ ┌─────────┐ │
│ │ 流程控制               │ │ │ 仪器管理(勾选) │ │ │ 报表配置 │ │
│ │ 产品信息/加电/断电      │ │ ├───────────────┤ │ ├─────────┤ │
│ │ 测波形/启动/暂停/停止    │ │ │ 仪器格 A       │ │ │ 总表     │ │
│ ├───────────────────────┤ │ │ (波形/参数)    │ │ │ 测量项列 │ │
│ │ 流程编辑（步骤树）       │ │ ├───────────────┤ │ │ 上下限   │ │
│ │ 加电→测量→计算→判定→报表 │ │ │ 仪器格 B       │ │ │ Pass/Fail│ │
│ │ 运行态：只读+高亮        │ │ ├───────────────┤ │ │ 导出HTML │ │
│ └───────────────────────┘ │ │ 命令日志(折叠) │ │ └─────────┘ │
└───────────────────────────────────────────────────────────┘
```

## 3. 窗口1 · 左区（流程控制 + 流程编辑）

### 3.1 上部：流程控制

| 分组 | 内容 |
|---|---|
| 被测产品 | 型号、序列号、测试条件（温度、操作员）、备注 |
| 电源控制 | 加电、断电（调用电源仪器的 `power` 能力） |
| 测量 | 单次测波形、读参数 |
| 流程控制 | 启动、暂停、继续、**停止**（自动回安全态）、单步 |
| 判据 | 进入报表配置（上下限、列映射） |

### 3.2 下部：流程编辑

- **编辑态**：步骤树可增/删/改/上下移动/另存为；步骤参数由"能力模型"自动生成表单；
- **运行态**：只读，当前步骤高亮（执行中/通过/失败/跳过），并显示该步骤返回值；
- 步骤来源：左区中部"可用步骤"列表（按能力分组，如 `电源`、`示波器`、`万用表`、`算法`）。

### 3.3 步骤类型（9 类）

| 类型 | 说明 | 关键参数 |
|---|---|---|
| `power_on` / `power_off` | 产品加电/断电 | 仪器、通道、电压/电流 |
| `set_param` | 设置仪器参数 | 仪器、参数名、值 |
| `measure` | 测量 | 仪器、测量项、通道、判据 |
| `wait` | 等待 | 时长 / 条件 |
| `compute` | **波形计算/算法** | 算法名、输入源、输出变量 |
| `limit_check` | 限值判定 | 变量、下限、上限 |
| `store` | 存库 | 记录字段 |
| `report` | 填报表 | 目标列 |
| `branch` / `loop` | 条件分支 / 循环 | 条件表达式 / 次数 |

流程 JSON 片段示例：

```json
{
  "flow_id": "demo-001",
  "steps": [
    { "type": "power_on",  "instrument": "power1", "params": { "channel": 1, "volts": 5.0 } },
    { "type": "wait",      "seconds": 0.5 },
    { "type": "measure",   "instrument": "scope1", "channel": 2, "measurement": "vpp",
      "limits": { "lower": 2.9, "upper": 3.1 } },
    { "type": "compute",   "algorithm": "fft_peak", "source": "scope1:ch2", "output": "peak_freq" },
    { "type": "limit_check", "variable": "peak_freq", "limits": { "lower": 950, "upper": 1050 } },
    { "type": "report",    "mapping": { "ch2_vpp": "Vpp列", "peak_freq": "峰值频率列" } },
    { "type": "power_off", "instrument": "power1", "params": { "channel": 1 } }
  ]
}
```

### 3.4 暂停 / 停止 / 单步

| 操作 | 行为 |
|---|---|
| **暂停** | 当前步骤执行完毕后停在**步骤边界**；暂停期间**不执行任何动作**（不下发命令、不采集、不计算），保持现状，等待"继续" |
| **继续** | 从暂停点恢复后续步骤 |
| **单步** | 每个步骤边界停一次（等同按步暂停/继续） |
| **停止** | 立即停止调度后续步骤，并**自动回安全态**：调用各仪器的"安全动作"（电源自动断电/输出关闭、信号源关闭输出等），然后结束本次流程 |

实现要点：
- 每个仪器在能力模型中声明 `safe_action`（安全动作），流程停止时由引擎统一调用；
- 停止过程本身要记录到事件总线（`engine.stop` → 各仪器 `hal.command` → `data.write`），架构台可看到"回安全态"的完整链路。

## 4. 窗口1 · 中区（仪器坞）

### 4.1 布局规则

| 显示仪器数 | 布局 |
|---|---|
| 1 | 单格占满 |
| 2 | 上下分栏 |
| 3~4 | 2×2 网格 |
| >4 | 前 4 格网格 + 其余标签页 |

拖拽分隔条调整各格大小；仪器清单勾选控制显示/隐藏；仪器数量不设上限。

### 4.2 仪器子模块结构

```text
┌─ 仪器格 ───────────────────────────────┐
│ 标题栏：[型号] 名称  ●连接状态  ✕ 隐藏    │
├────────────────────────────────────────┤
│ 自定义面板（每类仪器一套 QML 面板）        │
│  示波器：波形屏 + 6 设置页                │
│  电源：输出开关/电压/电流/实际值/保护       │
│  万用表：读数 + 量程 + 速率                │
│  信号源：波形/频率/幅度/偏移/输出           │
│  频谱仪：扫频设置 + 峰值表                 │
│  电子负载：模式/定值/读数                  │
├────────────────────────────────────────┤
│ 折叠区：该仪器的命令日志（最近 N 条）       │
└────────────────────────────────────────┘
```

- 运行自动流程时，用户仍可自由切换查看任意仪器；
- 仪器模块**全部由注册表动态生成**（新增仪器 = 加驱动 + 加面板 + 注册）。

### 4.3 虚拟电源（一期占位）

- 建议型号：**Siglent SPD3303X-E**（三路可编程直流电源，LAN SCPI）；
- 先用 mock 实现（加断电、设电压/电流、读实际值），真机到位后替换驱动，界面与流程不变。

|---|---|

## 6. 窗口2 · 架构台（只读展示 + 资产注册）

### 6.1 只读展示原则

- 展示区**不与内容交互**（点击不修改数据）；
- 允许的交互仅限：**展开/折叠板块、切换标签页**（用于查看被折叠的内容）；
- **例外**：非自动测试期间提供"资产注册"入口（见 6.3），属于配置动作，不影响展示数据。

### 6.2 板块内容（网格布局）

| 板块 | 展示内容 | 展示方式 |
|---|---|---|
| ① 表示层 | 两个窗口、页面与组件清单（QML 文件） | 卡片 + 文件树 |
| ② 胶合层 | Signal/Slot/Property 双向日志 | 命令日志表（方向/名称/参数/时间） |
| ③ 应用与算法层 | 测试样例（流程树）、方法库/**算法库**、引擎状态 | 流程树 + 库清单 + 当前步骤 |
| ④ 硬件抽象层 | 传输/协议/设备驱动清单、连接状态、命令流水 | 驱动清单 + SCPI/Modbus 日志 |
| ⑤ 数据层 | SQLite 表结构、最新记录、读写统计 | 表结构 + 记录表 |
| ⑥ 报告层 | 模板、生成记录、文件路径 | 清单 + 统计 |
| ⑦ 服务器层 | 灰显"本阶段范围外" + 未来接口 | 占位卡片 |

### 6.3 资产注册（非自动测试期间可添加）

在对应板块提供"注册"入口，新增的资产写入配置并**立即出现在窗口1 的相关位置**：

| 资产类型 | 注册位置 | 立即生效于 |
|---|---|---|
| 算法库（波形计算/数学模块） | 应用与算法层板块 | 窗口1 左区"可用步骤"列表 → `compute` 步骤可选 |
| 测试方法 | 应用与算法层板块 | 流程编辑的 `measure` 步骤可选 |
| 仪器驱动（传输/协议/设备） | HAL 板块 | 窗口1 中区"仪器管理"勾选清单可加入新仪器 |
| 报表模板列映射 | 报告层板块 | 窗口1 右区报表列可配置 |

> 自动测试运行期间禁用"注册"入口（与流程编辑同一规则：运行态只读）。

### 6.4 层间流转展示

两种手段组合（均由真实事件驱动，**不做流动动画**）：

1. **命令日志表**：
   - HAL 板块：SCPI/Modbus 命令与响应（含耗时、状态）；
   - 胶合层板块：Signal / Slot / Property 双向日志；
   - 应用与算法层板块：流程步骤执行与方法/算法调用记录；
2. **调用链时序**：一次测试（按 `corr_id` 关联）的完整链路按时间排序展示，形成"表示→胶合→应用→HAL→数据→报告"的调用链。
   可选增强：在层卡片之间用**静态连线**表示依赖关系，事件发生时仅**高亮对应卡片**（无动画）。

## 7. 事件总线（展示的发动机）

事件结构：

```json
{ "ts": "2026-09-15T10:21:33.412", "layer": "hal", "kind": "command",
  "action": "query", "detail": ":MEASure:ITEM? VPP,CHANnel2",
  "result": "3.0197E+00", "duration_ms": 8.3, "status": "ok",
  "source": "real", "corr_id": "run-0007" }
```

| 层 | 埋点 | 事件类型 |
|---|---|---|
| 表示层 | 按钮 → Slot | `ui.action` |
| 胶合层 | Controller/Panel 的 Slot 与 Signal | `glue.slot` / `glue.signal` |
| 应用层 | 引擎步骤、方法/算法调用 | `engine.step` / `method.call` |
| HAL | 传输读写、协议解析 | `hal.command` / `hal.response` |
| 数据层 | 存库/读库 | `data.write` / `data.read` |
| 报告层 | 生成报表 | `report.generate` |

- 环形缓冲 500 条，界面 5Hz 节流刷新；
- `source` 字段区分仿真/真机，界面明确标注；
- `corr_id` 关联同一次测试，便于展示完整链路。

## 8. 统一能力模型（混合模型）

### 8.1 概念

**能力模型** = 用声明式配置描述"仪器能做什么"，流程/报表/界面均以此为数据源：

| 能力 | 典型动作 | 典型测量项 |
|---|---|---|
| `power` | 输出开/关、设电压、设电流 | 输出电压、输出电流 |
| `voltmeter` | 设量程、设速率 | 直流电压、交流电压、电阻 |
| `scope` | 通道/时基/触发设置、启动停止 | Vpp、Vrms、频率、周期、上升时间 |
| `awg` | 设波形/频率/幅度/偏移、输出开关 | — |
| `spectrum` | 扫频、峰值搜索 | 峰值频率、峰值功率 |
| `load` | 模式（CC/CV/CR）、定值 | 电压、电流、功率 |

  "id": "power1",

  "protocol": "scpi",
  "device": "siglent_spd3303x",
  "capabilities": [
    {
      "name": "power",
      "actions": [
        { "id": "output_on",   "label": "输出开",
          "params": [ { "name": "channel", "type": "int", "range": [1, 3], "default": 1 } ] },
        { "id": "output_off",  "label": "输出关",
          "params": [ { "name": "channel", "type": "int", "range": [1, 3], "default": 1 } ] },
        { "id": "set_voltage", "label": "设置电压",
          "params": [ { "name": "channel", "type": "int" },

### 8.3 混合模式（保留逃生口）

| 层次 | 覆盖比例 | 说明 |
|---|---|---|
| 能力动作 | ~90% 常用操作 | 自动生成流程步骤表单、仪器面板控件、报表可选项 |
| 原生命令 | 剩余冷门功能 | 直接写 SCPI / Modbus 寄存器 / 自定义报文，作为 `action: raw` 使用 |

### 8.4 与现有模块的关系

| 现有 | 演进方向 |
|---|---|
| `autotest/core/methods.py` 方法库 | 变为"能力实现库"，按 `能力.动作` 注册 |
| `autotest/core/scope_commands.py` SCPI 映射 | 归入设备层（`devices/scope_rigol.py`） |
| `config/app_config.json` 仪器配置 | 扩展为 `config/instruments.json`（含能力声明） |
| 流程 JSON | 步骤从"方法名"改为"仪器+能力动作/测量项" |

## 9. 多协议三级抽象

```text
设备层 Device      示波器 / 电源 / 万用表 / 信号源 / 频谱仪 / 电子负载
   ↑
协议层 Protocol    SCPI 文本 / Modbus 寄存器 / 自定义二进制 / CAN 报文
   ↑
传输层 Transport   TCP Socket / Serial / VISA(VXI-11·USBTMC) / CAN 适配器
```

- 同一设备可换协议（如电源支持 LAN-SCPI 与串口）；
- 同一协议可驱动不同品牌设备（设备层做差异映射）；
- 新增仪器 = 传输（已有可复用）+ 协议（已有可复用）+ 设备驱动 + 能力声明 + 面板 QML。

### 界面（临时视图）
- 顶部新增 **"分层跟踪"** 开关；
- 面板列：时间 / 层 / 类型 / 动作 / 详情⇒结果 / 耗时；按层着色（UI 蓝、胶合青、应用绿、HAL 橙、数据紫、报告灰）；
- 头部显示统计：事件总数、存储数、轮询噪声数、各层计数；提供"清空"。

### 关键机制
1. **噪声上下文**：波形/读数轮询经 `bus.quiet()`，事件只计数、不入缓冲，避免淹没关键链路；
2. **埋点零侵入**：`publish/span` 内部吞掉所有异常，绝不影响被测流程；
3. **线程安全**：流程在后台线程执行，事件经 Qt Signal 排队投递到界面线程；
4. **关联号**：流程启动时 `bus.set_correlation(test_id)`，同一次测试的事件可用 `corr_id` 串联；
5. **数据源标记**：真机=`real`、仿真=`sim`，界面/日志可区分。
